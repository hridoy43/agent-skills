# Evidence-led product design

For product, UX, and behavior decisions on any platform.

1. Define user, problem, desired behavior, outcome, and constraints; state the hypothesis before the implementation.
2. Pick proportionate evidence: analytics, research, usability tests, domain research, support data, or a small experiment.
3. Analyze the whole journey: entry, progress, success, loading, empty, error, recovery, return.
4. Label claims `observed`, `supported`, `inferred`, `hypothesis`, or `unknown`. Popular products, articles, and frameworks are hypotheses; keep source, date, method, and limits.
5. Define primary metric, diagnostics, guardrails, baseline, segment, and validation method (HEART or similar when useful).
6. Check accessibility, trust, privacy, safety, dark patterns, and unintended incentives.
7. Ship the smallest useful slice, validate, and record what changed or remains uncertain.

By area: onboarding optimizes first meaningful success, not screen count; monetization and checkout cover timing, uncertainty, recovery, and lifecycle; gamification and notifications only when tied to real user value (no default streaks, points, or urgency); dashboards answer a user question and lead to a next action; forms remove effort without removing needed information; progressive disclosure never hides required information.

Marketing surfaces, pricing, and conversion onboarding: use `conversion-storytelling` for narrative, proof, CTA, and conversion measurement; this skill keeps the hypothesis, flow, technical boundary, and validation handoff.

```text
Outcome / Owning feature / Segment / Hypothesis / Evidence and provenance / Observed vs inferred /
Flow and states / Primary metric / Guardrails / Risks / Smallest validation / Decision and follow-up
```
